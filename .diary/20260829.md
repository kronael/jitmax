### What the audits found, and what shipped

**CTO review — the top finding was a clean run that checked nothing.** A file
importing a type from a package that is not installed gets `any` for that type,
so `objectShapes` counts nothing, `isArray` answers false, every type-based rule
goes quiet, and the run printed `every annotated function is clean` and exited
0. That is TC-7 and TC-17's failure class in the one shape still standing.
`scan()` now returns the specifiers the program could not resolve, names them
above the findings, and exits 1. Asked of the checker — an unresolved specifier
has no symbol — which costs 8ms over typescript-eslint's 230 files where
`getSemanticDiagnostics` costs seconds. On that checkout it names all 20
uninstalled packages, which is TC-51's actual cause rather than its symptom.

**Two exit-2 crashes on legal source (TC-71).** `targetsOf` followed
`const g = h` to `const h = g` until the stack ran out; the `i < 8` cap beside
it bounds the loop and never bounded the recursion, which is a guard that reads
like protection and is not. And any token starting with a dash became a disable
key, so `/** @jitmax -- benchmarked 2026-01 */` produced the key `-` and killed
the run. Exit 2 means the tool failed; neither of these programs is that.

**The install path was false (TC-72).** README told you to `npm install
<repo-url>` and then `npx jitmax`. A packed install dies at startup: Node
refuses to strip types from a file inside `node_modules`. A local install from a
path SYMLINKS, so the file resolves outside `node_modules` and appears to work —
which is why nobody here ever hit it. Recorded rather than fixed: shipping a
`dist/` or deleting the `bin` field is packaging, and it is bound to the licence
and publish decisions in TC-50.

**A bullet in Honest limits said the opposite of the data.** It claimed two
unreplicable cells "are inside a range this page quotes". They are not — the
ranges are 4.64-4.95x and 12.3-13.6x and both withdrawn triples fall outside.
It had contradicted a paragraph 480 lines above it since rule 13 was enforced,
and survived because the test asserts prose CONTAINS each derived value and
cannot see a false sentence built around them. TC-73 records the general gap:
53 ratios in README prose, 31 not derived — most of them honest history, which
is why the page's blanket rule cannot simply be copied here.

**Sonnet review of the day's code — three defects, all real.** A destructuring
assignment stores and never loads, and the access sits under a literal rather
than under the `=`, so `[r.x] = [5]` counted as a read and fired
megamorphic-elements on a body that loads nothing: TC-8 again, in the shape its
fix missed. The suppression line was counted per mark while the findings above
it were counted per site. And `literalBound` read only the first argument when
negative, so `slice(-10, -5)` bounded to 10 instead of 5 — latent at the current
threshold and fixed before it is not.

**CEO review — "do not adopt as a linter."** The flagship rule firing at 8
distinct lines in 2953 functions is a null result, not a feature. The asset is
the measurement protocol and the refutations. Recommendation: relicense off
GPL-2.0-only, publish, and give the evidence to oxlint and Biome, who ship two
of these rules on a blog post and a WebKit citation. Owner decision, recorded
under TC-50.

**ELI13 read — the output justifies itself instead of telling you what to do.**

errors, or disable the rule". And the `accumulating-spread` fix on radash is a

### TC-10 shipped: the walk enters constructors

`new Foo()` is a NewExpression and `reach()` visited CallExpression only. One
thing the entry's plan did not anticipate: `new Foo()` resolves to the CLASS,
not to a body, so a class is expanded to its constructor before the followable
test — and a readable class declaring no constructor runs a default one with no
body, neither followed nor reported. Without that case every `new Plain()` in a
program becomes a false escape.

### The collision, and what it cost

A second session was editing `lib/report.ts`, `lib/scan.ts` and the `Makefile`
at the same time, adding platform detection by import specifier — which works
where `@types/node` is not installed, and is better than what was there. A
report rewrite written here was overwritten by their save and is gone. Nothing
committed was lost; the loss was one uncommitted rewrite and the time to find
out.

Their new test then failed against this session's unresolved-module change,
correctly: an unresolved `node:path` is not blindness, because the specifier
alone says it is the platform. `unresolvedModules` skips Node specifiers now,
and the tree is green at 94 tests with both sessions' work in it.

**The lesson is the one already in CLAUDE.md and it applies to sessions, not
just subagents: two writers on one tree, and the last save wins.** The fable
report redesign is designed, reviewed and NOT applied, for exactly this reason.
