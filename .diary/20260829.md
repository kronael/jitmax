### What the audits found, and what shipped

**CTO review — the top finding was a clean run that checked nothing.** A file
importing a type from a package that is not installed gets `any` for that type,
so `objectShapes` counts nothing, `isArray` answers false, every type-based rule
goes quiet, and the run printed `every annotated function is clean` and exited
0. That is TC-7 and TC-17's failure class in the one shape still standing.
`scan()` now returns the specifiers the program could not resolve, names them

has no symbol — which costs 8ms over typescript-eslint's 230 files where
`getSemanticDiagnostics` costs seconds. On that checkout it names all 20
uninstalled packages, which is TC-51's actual cause rather than its symptom.

**Two exit-2 crashes on legal source (TC-71).** `targetsOf` followed
`const g = h` to `const h = g` until the stack ran out; the `i < 8` cap beside
it bounds the loop and never bounded the recursion, which is a guard that reads
like protection and is not. And any token starting with a dash became a disable
key, so `/** @jitmax -- benchmarked 2026-01 */` produced the key `-` and killed
the run. Exit 2 means the tool failed; neither of these programs is that.

**The install path was false (TC-72).** README told you to `npm install
<repo-url>` and then `npx jitmax`. A packed install dies at startup: Node
refuses to strip types from a file inside `node_modules`. A local install from a
path SYMLINKS, so the file resolves outside `node_modules` and appears to work —
which is why nobody here ever hit it. Recorded rather than fixed: shipping a
`dist/` or deleting the `bin` field is packaging, and it is bound to the licence
and publish decisions in TC-50.

ranges are 4.64-4.95x and 12.3-13.6x and both withdrawn triples fall outside.

### TC-10 shipped: the walk enters constructors

`new Foo()` is a NewExpression and `reach()` visited CallExpression only. One
thing the entry's plan did not anticipate: `new Foo()` resolves to the CLASS,
not to a body, so a class is expanded to its constructor before the followable
test — and a readable class declaring no constructor runs a default one with no
body, neither followed nor reported. Without that case every `new Plain()` in a
program becomes a false escape.
