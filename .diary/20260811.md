# 2026-08-11

## The recursion, which was the whole point

`@njit` compiles the function **and everything it calls**. turbocharge checked
one function and reported every helper it reached as the end of the world. The
owner put it plainly: *"njit is doing recursion, that's the whole point."*
Correct, and the spec had admitted the cost in writing since it was written —
§1 said the first run on real code is "a wall of closed-world findings" and §9
"owes an answer for it". No answer had ever been delivered.

Now `scan.ts` walks from each annotated root into every callee whose source is
in the program, with a visited set for cycles and a hard cap of 200 bodies. All
five measured rules run over every body in that set. `closed-world` stopped
being a nag about un-annotated helpers and became the edge report: the calls
that left your source into `node_modules`, so you can see how much of the run
was actually checked.

Two bugs fell out of building it:

1. TypeScript ships `lib.es5.d.ts` **inside `node_modules`**, so every `.push()`
   and `.reduce()` was being reported as somebody's unchecked dependency. Fixed
   with `program.isSourceFileDefaultLibrary()`.
2. A finding inside a callee printed under the annotated function's header with
   no location of its own — a riddle, not a report. It now prints the callee's
   `file:line`.

## The harness was lying, and it was lying in our favour

A subagent was sent to add a `chained-allocation` rule. It came back having
refused to ship it, and having found why: `driver.js` sized each timed region
from a single cold `reps=1` probe. A cold run of the chained pipeline reads
1,000-20,600 ns/op against a warm ~21. So the chained side got **11 reps** where
the fused baseline got 1,294 — a **2.4 ms timed region against the protocol's
120 ms target**. It was timing interpreter warmup against optimized code.

The bias is structural and directional: **the slower a variant runs cold, the
fewer reps it gets, the less its warmup is diluted, the more its ratio
inflates** — worst for exactly the variants a rule wants to indict. The harness
manufactured the effect it was asked to find. That is the round-1 ordering
artifact all over again, in a new place.

Fixed in two stages. First: iterate the probe until two estimates agree within
20%. That converged everywhere except the L3 cells, where a memory-bound kernel
varies more than 20% run to run and the agreement test was demanding stability
the machine does not have. Second, and correct: iterate a fixed six times to
reach warm cost, then take the **median of the last three**. The guard that
actually decides publishability is separate — a cell whose achieved region
misses 120 ms by more than 2x now **throws**, and `cellOrVoid` records it as
VOID so one bad cell no longer takes the sweep down with it.

## TC-6: half an hour of measurement that was never on disk

While the 24-cell sweep printed results to the terminal, `ls bench/*.jsonl`
showed no output file. `/proc/<pid>/fd` held no regular file at all. The sweep
body blocks the event loop end to end in `execFileSync`, so the write stream's
asynchronous `open()` callback never fires and every row sits in the buffer
until the process exits. The twelve cells from the run I killed earlier were
never written anywhere. All three runners now `appendFileSync` one row per
cell.

## What re-measuring changed

Every sweep re-run under one protocol. Old files kept, never overwritten:
`*-precal.jsonl` and `*-oldcal.jsonl`.

- **Five-shape reads: 3.61-10.59x**, against the published 3.4-8.7x. The old
  harness was *under*-reporting the cliff, because the fast baseline was
  getting cold-inflated too.
- **Below the cliff is now measurable.** 2/3/4 shapes cost 1.15-1.97x, nearly
  every cell excluding 1.0. The old harness could not resolve anything under
  1.7x, so the rule stayed silent below five because the cost was *unknown*.
  It now stays silent because the cost is *an order of magnitude smaller*.
  Better reason, same threshold, and the must-stay-silent test still passes.
- **Accumulating spread: 177x at n=1,000 and 2348x at n=10,000.** The claim
  that a spread-built array *reads faster* died — 0.96x and 0.98x, which is
  nothing. It was a calibration artifact, exactly as predicted.
- **Chained allocation shipped after all: 7.13x at n=1,000 (CI 6.64-7.64).**
  The 19.73x that got it refused was the harness talking. Its silent case is
  the best in the set: at n=100,000 it falls to 1.45x, because memory bandwidth
  takes over and one extra allocation stops mattering.

Six rules now, 616 lines, 15 tests. The meme is generated from the calibrated
sweep including its headline number, so the picture cannot drift from the
measurement — it says 10.6x because the data says 10.6x.

## The site was off-brand and nobody had read the spec

The owner said the page was "totally fucked". It was: it linked
`/pub/assets/hub.css`, the **arizuko** sheet, whose `--accent` is the gold that
`/pub/krons/CLAUDE.md` explicitly names as wrong for krons — then pasted green

components only, the three `krons:*` catalogue metas, `.back-btn`, 3px radii,
and no colour overrides. Also written down as a memory, because the two
same-named stylesheets are a trap that will catch the next person.

Added: `README.md`, which did not exist.

## The framing was wrong, and the owner caught it twice

First: *"njit is doing recursion, that's the whole point."* Right — and the spec
had confessed the gap in writing since it was written, then never closed it.

Second, and sharper: **the reason turbocharge is not njit is not that we cannot
compile TypeScript. It is that V8 already does the job well.** Numba must
compile because CPython does not JIT at all. V8 does, and does it well, so this
tool never needed to be a compiler substitute — its whole job is to say where
your code takes away optimizations V8 would otherwise have applied. Every doc
said "we cannot compile, so the verb changes", which framed a strength as a
limitation. Corrected in SPEC §1, README, the page, and the one comment in
`scan.ts` that still carried it.

Third: njit is gone from the onepager entirely. It survives in README as prior
art, one paragraph, clearly labelled motivation. A product that has to explain
itself through a Python library the reader may not know is not shipping as
itself.

## Three audits, run rather than imagined

CEO, CTO and go-to-market, as read-only subagents against the live page with
the repo as source of truth.

**GTM: no-go, for a bug I would have shipped.** `og:image` pointed at
`meme.svg`, and X's card crawler does not render SVG — it drops the image
silently. The page whose entire social strategy is a screenshot-bait chart had
no working social card. Now a real 1200×630 PNG, rasterized from the same SVG
inside `make meme-png` so it cannot drift, with absolute URLs and dimensions.
It also caught the structure: the chart led before the reader knew what the
tool was, and the "why not just use Biome or oxlint" answer sat six screens
down. Pitch first, chart second, competitor answer in the TL;DR.

**CEO: 38/100, and one finding was a real defect.** The walk stopped at its
200-body cap *silently*, so a partially-checked function could report nothing
and the run could still print "every annotated function is clean". A checker
that quietly checks less than it claims is the exact failure this project
exists to prevent — and the page had been admitting it in its own limits
section. Now it prints `WALK TRUNCATED` and refuses to call the run clean.
Logged as TC-7.

Two CEO blockers stay open because fixing them would mean inventing facts:
there is no `LICENSE` and no `license` field, so nothing here is legally
adoptable; and there is no public repo, so the page has no call to action.
Both are the owner's to decide.

Also fixed from the audits: `.hub-subtitle` was being used for body copy and I
had invented a `.note` class. Every class on the page is now a documented
hub.css component — the same rule I had written into memory that morning after
getting it wrong the first time.
