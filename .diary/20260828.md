### The project is jitmax

`turbocharge` was taken on npm and npm's dispute policy refuses transfers on
demand; bare "turbo" returned 3,991 packages and Vercel claims **Turbo** as a
brand. `registry.npmjs.org/jitmax` returns 404. That settles the name half of
TC-50; the relicensing half is untouched and still the owner's.

Everything live carries the new name: sources, docs, tests, examples, Makefile
targets, `bin/jitmax.ts`, the annotation `/** @jitmax */`, the package name and
the meme assets. V8's own `TurboFan` and `--trace-turbo-inlining` are untouched.

`bench/*.jl` and `.diary/` keep the old name deliberately. A `.jl` row is a
record of a run that happened and the diary is a log of when it happened;
rewriting either would make both say something untrue. One `.jl` row carries a
stale absolute path inside captured stderr — that is what the path was.

### Four things the rules were claiming and could not support

The owner walked the rules and found them over-claiming in four ways. Three were
already in `BUGS.md` as registered defects — TC-8, TC-9, TC-33 — logged and
never fixed.

**TC-8.** `megamorphic-elements` reported a megamorphic load from a parameter's
type without checking that anything read a property off an element. `return
rows.length` loads off the ARRAY, whose map does not change with the element
type. It now requires the read, and it is narrowed to a READ rather than to any
inline-cache site: V8 charges the same four-map budget at a StoreIC and at `in`,
but the sweep measures `s += r.x + r.y`, so firing on `r.x = v` would quote a
read's number for a write. `in` is the known gap and the code says so.

**TC-52 (exit codes).** Every finding set exit code 1, `closed-world` included —
and that rule was 97% of every finding across 22 codebases, so it decided nearly
every exit code on evidence this project does not have. Findings are now `error`
or `warn` and only an error fails the run. The owner's wording: warn does not
fail. This replaced the `bound` flag, which existed to change one printed word
and had no reader left once the cost line went.

**TC-9.** The cost is out of the finding. A ratio is a property of the input —
accumulating spread is 149-166x at n=1000 and 1766-1889x at n=10000 — and the
annotation asserts the function is hot, not how large its data is. The finding
names the sweep; README carries the number. This was the owner's own proposal
and it supersedes the "up to Nx" wording discussed the same day.

**TC-54 and TC-55**, both found by running the tool over 67 files nobody wrote
for it. A `.slice(0, 10)` in a matched chain bounds the intermediate array to ten
elements, three orders of magnitude under the smallest cell `bench/chained.jl`
carries — the one place a rule can read its own `silent` clause off the source
instead of guessing, and it walked over it. And 157 of 157 notes in that run were
`closed-world` advising the reader to inline `path.join`. A callee under
`@types/node` is native: counted for the run, never listed.

### The survey caught the fix overshooting

Re-running 22 codebases is what turned TC-8 from a caveat into a measurement:
vue 46 findings before, 8 after — 38 of 46 were functions touching nothing but
`rows.length`. It also showed the fix had gone too far. zod's `prefixIssues` is
`(iss as any).path.unshift(path)`, so reading the receiver's type off the cast
returned `any` and the one true instance of this rule in twelve libraries went
silent with the false ones. A cast is a claim about the type checker, not about
the object. Receiver unwrapped through `as`, `<T>`, `!` and parentheses; zod back
to 10, vue still 8, TypeScript 19 → 5, 23 across all 22.

The twelve-library table had also drifted: rule narrowings landed after it was
published and it was never re-run. Re-run now, and README says so rather than
quietly carrying new numbers under an old date.

### Hotness is measured now, not asserted

TC-57 asked for a whole-codebase mode that finds the hot paths itself. Static
inference did not ship and is recorded as refused, not deferred: a loop with an
unknown trip count is weakly predictive, call-graph fan-in needs a reverse graph
whose edges through parameters and interfaces already vanish (TC-31), and this
tool prints "hotness is a property of the workload" under every run it makes.

`jitmax run.cpuprofile src` reads V8's own profile instead. Self time per frame
from `samples` and `timeDeltas`, every function at or above `[profile]
min_self_pct` marked, and the report says what marked it. Downstream is
untouched — `reach()`, `check()` and `render()` cannot tell a profiled mark from
an annotated one. Two loud failures: a profile matching no function is exit 2,
because that means it was taken against different source; an unmatched hot frame
is counted and printed.

What the design did not predict: V8 reports a function's position as its
parameter list's `(`, not the `function` keyword. Every arrow matched and every
function declaration did not. The index carries both positions.

### TC-60 verified rather than believed

The entry claimed seven typed arrays reach a load site as seven V8 maps.
`%HaveSameMap` under `--allow-natives-syntax` says false for all 21 pairs, and
the seven prototypes are seven distinct objects. The claim is a measurement now.
The conclusion — that the cheap fixes are wrong — is unchanged.

### The second half of the session: the queue kept filling, and the counting was wrong

The owner wrote nine more entries while the above was landing (TC-52 through
TC-69, renumbered), several of them from running the tool over 30 corpora and
11,198 mechanically annotated functions. Shipped from them:

**TC-62 — a finding is one per SITE.** A line reached from 28 annotated
functions was 28 findings, so every count this project has ever published was
the call-graph fan-in rather than the work. `agent-twitter-client` reported 118
errors over 12 distinct lines. The TypeScript compiler went from 90 errors and
677 warnings to 24 and 77, with 666 repeats collapsed. The fan-in is kept and
printed on the finding, because a line reached by 28 callers is a better fix
than one reached by one.

**TC-63 — `delete process.env.X` deletes nothing V8 owns.** Node implements
`process.env` with a named-property interceptor; there is no hidden class to
demote. Not TC-9's "the number is the wrong size" — the mechanism the finding
names does not exist at that site. The first attempt tested for any
`lib.*.d.ts` and silenced `delete o[k]` on a `Record<string, number>`, which is
the exact program the benchmark measured. `@types/node` and the DOM only.

**TC-45 and TC-69 — the walk was silent about what it could not follow.** The
escape test required the callee to be types-only or unresolvable, so a call
resolving to an interface member — a body that IS in the checkout — fell through
both branches and vanished. It is now reported, and it says which of three
causes it is: platform, missing dependency, or interface dispatch. Following the
interface to its single implementation did NOT ship: it needs a program-wide
index, and being wrong means claiming coverage the walk does not have, which is
worse than the flood.

**TC-48 — the last hand-typed size.** `delete-property.cost` claimed
"(n=16384 and n=262144)" beside a ratio that excludes n=262144, because rule 13
withdrew that cell. `delete.rows.sizes` derives it and renders `n=16384`.

**The recount is the result worth keeping.** Per site, across 22 codebases and
2953 annotated functions: 205 errors, not 671. The flagship rule's whole
footprint is **eight lines** — five in the TypeScript compiler, two in vue, one
in zod. It printed as 23 because ten of zod's were one site reported from ten
roots. TypeBox's 119 accumulating-spread findings are 29 distinct sites, still
more than every other codebase here put together. TC-64 reaches the same place
from 30 other corpora by a different route.

### Reconciling two surveys that disagreed

TC-64 said `megamorphic-elements` fired zero times in 11,198 functions; the
22-codebase run said 23. Both are right. TC-64 annotates `export function` and
class methods, and vue's two real instances — `hasForwardedSlots` and
`condenseWhitespace` — are module-private; `grep -c 'export .*<name>'` is 0 for
both. zod's are exported but were silent between 0cf1005 and df8aafb, when the
receiver type was read off a cast. The narrower statement still stands and is
still bad for the rule.
