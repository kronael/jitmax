## 2026-08-30

The owner's read of the escape rules: they should count how the system calls
them and route to megamorphic when the count says so, and `closed-world` should
fire on outside functions rather than on builtins. Both were right, and the
second one uncovered a third defect nobody had asked about.

### The count was taken on one side only (TC-98)

`lib/scan.ts` called `flow.receiver()` inside the `isDispatchDecl` arm, so
`Call.dispatch` was `undefined` for every escape `closed-world` received. It
therefore said the same sentence about two very different sites:

    calls pickOne, which we have no body for; the promise stops here

for `const pickOne = flag ? left : right`, where the callee walk finds a
variable and no function while the dataflow walk finds two — and for a receiver
that five classes from a typed dependency reach. The maps reaching a receiver
decide the inline cache whether or not the callee's body is readable, so the
question belongs at both. `megamorphicCall` is now one exported function in the
rule that owns the claim, called first by both escape rules. It refuses a site
with no receiver: five functions reaching `f()` is call-target feedback, which
`bench/dispatch.jl` varies only over one property set, and this project does not
price a mechanism its sweep never isolated.

### The platform test read the wrong end of the call (TC-98)

`globalThis.gz()` resolves its callee to the `declare global { var gz }` the
program itself wrote, and `(0, eval)` to a binary expression with no symbol at
all, because the callee walk unwrapped parentheses and nothing else. Both read
as somebody's unreadable code and got "inline what you need from it", which is
the same complaint TC-55 filed about 157 notes on `path.join`. `intoHost` reads
the platform off the RECEIVER's leftmost name — its DECLARATION, never its type,
because testing the type is how the first attempt at TC-63 silenced the case its
benchmark measured — and `unwrap` sees through a comma expression now.

### Re-running the survey found the count was wrong three ways (TC-99)

The counting fix looked right on fixtures and produced 54 `megamorphic-dispatch`
findings on valibot, which is the kind of number that is a bug until proven
otherwise. It was three:

- **Every array literal was its own map.** `originOf` keys an object literal by
  its sorted property names — TC-42's direction — and keyed everything else by
  node identity. valibot has 34 `dataset.issues.push()` sites, each printing "at
  least 10 implementations", all ten `array (…)` from ten files. An array's map
  is its elements kind, not its allocation site. One key now.
- **An origin without the method still counted.** The walk is path-insensitive,
  so `if (isArray(source)) source.some(…)` is invisible: vue's `watch.ts:161`
  counted 34 object literals at a call only an array can make, every one from a
  `.spec.ts`. An object literal without a spread carries exactly the names it
  spells plus `Object.prototype`'s, which makes the test exact for it. Classes,
  arrays and spread literals are left alone.
- **`any` receivers were counted as if declared.** es-toolkit's
  `isPlainObject(object?: any)` counted 42 shapes at an `object.toString()` a
  `typeof` guard three lines up admits one kind of value to. `Dispatch.typed`
  gates the megamorphic route; below the gate the count is still printed and
  says what it is.

54 became 1 on valibot, 21 became 0 on es-toolkit, 21 became 10 on vue.
Path-insensitivity is the cause of all three and none of the fixes touch it.

### What the survey says now

Re-measured across all 22 codebases. The two escape rules are 1490 of 1546
findings in the twelve libraries, 96%, unchanged in share and split 1427/63.
`closed-world` loses 328 findings on the TypeScript compiler alone, all of them
the host.

`megamorphic-dispatch` fires three times in the twelve libraries where it never
fired at all, and all three are dispatch tables written on purpose: immutable's
`Seq.js:65` and `:83` call `this.__iterateUncached()` and
`this.__iteratorUncached()` on a `this` that ten `Seq` subclasses reach, and
date-fns's `parse` calls `this.parse()` on a `this` that 31 parser classes
reach. The rule found the two places these libraries chose polymorphism, which
is the honest reading of it.
