# 2026-08-10

## turbocharge: built, measured twice, corrected twice

The checker exists and runs. `bin/turbocharge.ts` + `lib/*.ts`, 475 lines of
TypeScript executed directly by Node (type stripping, default since 22.18, so
no build step). `make test` 9 passing, `make lint` clean, `make check`,
`make bench`, `make publish`.

**The framing that unlocked it: Numba's `@njit`.** Mark a function; it checks
out or fails loudly. That produced the closed-world rule — an annotated
function reaches only annotated functions and a primitive list, and every other
call is reported as the point where the promise stops. This answered the
question SPEC §1 had been dodging since it was written: where does the analysis
stop. It stops at a declared edge, and the fix for a finding is to annotate the
callee, so coverage spreads outward through the hot call graph.

### Two corrections, both from measurement

1. `megamorphic-elements` shipped firing at **three** shapes while quoting a
   **five**-shape cost, across a gap nobody had measured. Measuring 3 and 4
   showed 2/3/4 are all ~1.3x and the fifth is 4-8x. Threshold moved to 5.
2. Re-running the entire 24-cell sweep killed the replacement numbers too.
   **Nine of 24 cells did not replicate.** Every effect between 1.0x and 1.7x
   flipped between significant and rejected; one flipped direction. Every
   five-shape reads cell held, 3.4-8.7x, six for six. So the harness resolves
   the cliff and cannot resolve anything below it, and all the 1.18-1.58x
   figures were withdrawn as point estimates — including the ones already
   published.

The second correction is the one worth keeping. The rule now stays silent below
five shapes for a better reason than "the effect is small": *we cannot measure
it*. It also put a caveat on `boxed-elements`, whose 1.45-1.89x comes from one
unreplicated sweep inside exactly that unresolvable band. The tool says so in
its own output now.

### V8's source agreed with the benchmark

Sparse-cloned github.com/v8/v8 (96 MB, `src` + `include`).
`DEFAULT_MAX_POLYMORPHIC_MAP_COUNT 4` at `flags/flag-definitions.h:3320`,
enforced at `ic/ic.cc:802`. The benchmark and the constant are the same fact
found from opposite ends — the only rule in the project with both. SPEC §12
tables eleven more constants as candidates; none ship, because a constant is a
hypothesis and only a benchmark makes it a rule.

Also verified but unshipped (BUGS TC-3): above ~3456 generated statements V8
never optimizes a function at all, costing 2.74x per statement. I suspected the
edge was a tier-up budget artifact, pushed to 3,000,000 invocations at three
sizes, and it held.

### Go is the wrong axis

Our own code is 8-10 ms, under 1% of a run; `createProgram` plus the checker is
89%. TypeScript 7 (`microsoft/typescript-go`) is the Go port of that compiler,
but every package is under `internal/` — Go-enforced, no `pkg/` — so it cannot
be linked from Go either. The sanctioned path is `internal/api`, a
jsonrpc/msgpack server over a unix socket, which makes a Go client and a Node
client identical. Its protocol exposes exactly the six calls our rules make,
`getIndexTypeOfType` among them. So the ~10x is a **client swap, not a
rewrite**, and it stays in TypeScript.
