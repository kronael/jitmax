## 2026-08-31

The v0.11.0 release, and the release gate did not survive the release.

### The gate had been false for a whole release (TC-123)

`CLAUDE.md` closes with "Reality check before any release:
`node bin/jitmax.ts tmp/demo-real/src` against a radash checkout must report
exactly one finding. More than one means a false positive shipped." Run today it
reported ten. Measured across tags on the same checkout:

| ref | result |
| --- | --- |
| v0.9.0 | 1 error — the gate passes |
| v0.10.0 | 1 error, 11 `closed-world` warnings |
| 552401d | 1 error, 9 `closed-world` warnings |

So the gate did not break today; it broke at v0.10.0, and v0.10.0 shipped under
it. The cause is `100f22f`, which widened the escape test to "nothing was
followable" because the old test dropped a call resolving to an interface member
through both branches and reported it nowhere — "a coverage report that silently
omits a case is the lie this rule exists to prevent". radash's `getter`,
`mapper` and `condition` are exactly that case. They are `warn`. The error
count, which is the tier that fails a build, is 1 at v0.9.0 and 1 today.

The gate counts errors now. The half NOT fixed is the one that matters more:
nothing runs it. `make v8-check` exists so the citation evidence cannot rot in
silence; the reality check was prose, so it did. A `make reality` target is the
cause fix, needs a documented checkout path, and is recorded rather than bundled
into a release.

### The same defect, twice more, in the presentation surfaces

README line 681 said "all eight rules" and line 906 said "seven rules". A rule
had been added and one of the two sentences moved. Neither surface's version
string was checked against `package.json` either.

`make test` now holds both to their sources: README's `Status:` line and the

which is a subset and counts something else. Anchored to the two statements and
to totals only, it passes, and it fails when the version is moved by hand.

### The hole-hunt found a false-clean, and the guard I had just written missed four figures

Three read-only audits against the tag, one bucket each: the published surfaces,
the tool, the evidence pipeline. Two found real defects.

**TC-124, the worst kind of bug this project can have.** JSDoc above the first
overload — where JSDoc for an overload set conventionally goes — printed
`every annotated function is clean` at exit 0 over an implementation holding
`accumulating-spread`. `isFunctionLike` tests the NODE KIND; an overload
signature is a `FunctionDeclaration` with no body, so the walk walked a node
with no children, `truncated` stayed false, and nothing downstream could tell
"walked and found nothing" from "had nothing to walk". `withBodies()` binds a
body-less mark to the declaration of the same symbol that has a body, and when
none does the name goes on a third `Blind` channel — the seam that interface's
own comment had already anticipated.

**TC-125, and it is the more embarrassing one.** The guard written this morning
for TC-123 was green while the exact bug it was written to catch shipped on both
public pages. It matched `all N rules` and the `Status:` line, and never looked
at "Seven rules ship." — the sentence that introduces the rule table on both
surfaces — nor at the site's rule count at all. Beside it: "67 unit tests"
against a real 126, and a site row crediting `closed-world` alone with 98.8% of
all findings, a figure that belongs to three rules and was re-measured to 98.6%.
The landing page listed six of eight rules; `megamorphic-dispatch` and
`interface-dispatch`, this release's headline, were not on it.

Writing the missing dispatch row, I quoted 14.59-19.97x from memory and the
project's own derived-number test rejected it. The derived figure is 12.9-22.7x.
The lesson the repo already knew, applied to me.

## 19:45 2026-08-31

### First-contact audit before changing the product

The clean Valibot checkout was the decisive failure: running jitmax over its
TypeScript source printed `0 annotated functions` and then `every annotated
function is clean` at exit 0. The command worked, but checked nothing. The
survey copy with temporary marks found 10 errors and 123 warnings in 87
functions; the 919-line report made the useful findings hard to see.

The existing radash reality gate still found its intended accumulating spread.
Profiling jitmax while it scanned Valibot exposed a second false-clean shape:
the default one-percent self-time threshold selected no project functions and
reported success. Reusing that valid profile at 0.05 percent selected 21 hot
functions and found three real chained allocations in `flow.ts`, `shared.ts`,
and `scan.ts`, but also printed 362 unmatched dependency/runtime frames and a
1,448-line report.

This changes the product priority. Packaging is a small mechanical fix. Honest
zero-work output, project-owned profile accounting, and a compact error-first
report decide whether the first run is useful. Automatic discovery must remain
a labelled non-gating suggestion until real profiles show that its selector
finds hot code reliably.

## First-run evaluation after v0.12.1

The install contract now survives its real boundary. A packed tarball installed
under `node_modules`, `npx --package <tarball> jitmax`, and
`bunx -p <tarball> jitmax` all checked the unchanged radash `assign()` example,
printed one `accumulating-spread`, and exited 1. No path used a source symlink.

The leading command no longer says `jitmax src`. Bare `jitmax` from the target
repository root reads its `tsconfig.json`; the explicit path was the degraded
form on bundler-resolution projects. A run with no annotation now names the
exact next action: add `/** @jitmax */` above one hot function and run again.
An empty profile selection tells the user to confirm the workload reached the
code or lower `min_self_pct`. Commit `73888d9` holds both behaviors and their
tests.

The same real-use pass rejected a larger profile change. At 0.05%, jitmax's own
profile produced 375 unmatched TypeScript dependency frames, 46 errors, and 305
lines for 11 project functions. TC-132 records the required contract: partition
program, dependency, and runtime time, then apply the threshold to program-owned
self time. That changes profile semantics and remains a proposal.

The CEO verdict is PILOT for named hot functions. The CTO verdict is TRIAL for
manual developer use, not a repository-wide CI gate. The marked Valibot run is
the reason: 107 errors in 768 lines, 95 from `closed-world`. The detector found
real code, but the coverage signal dominates broad-run output.

Verification after the change: 156 tests pass, all 14 V8 citations match the
pin, and the radash reality gate returns its pinned 10-error composition.
