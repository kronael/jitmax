
## 07:55 2026-08-13

Released v0.2.0 (version sync), then added a seventh rule and released v0.3.0.

**`allocating-select`.** The pattern came from a real review of somebody else's
code: `bucket.slot_from = Decimal.min(bucket.slot_from, item.slot)`.
`Decimal.min(a, b)` never returns `a` — it builds a new Decimal — so the line
allocates on every block, including every block where the incumbent already
wins, which with chronologically ordered data is every block after the first.
`slot.lt(bucket.slot_from)` compares without allocating and stores only on a
real minimum.

The other half of the same review was the counter-example: `Math.min` on two
numbers is lowered to a machine instruction, so guarding it with a branch saves
one field store and nothing else. Both halves went into the benchmark, and the
second one is what defines where the rule stays quiet.

**`bench/select.jsonl`, six cells.** Running minimum over 32 buckets, boxed
values, `Box.min(b.lo, v)` against `if (v.lt(b.lo)) b.lo = v`:

| mode | n=10,000 | n=100,000 |
|---|---|---|
| chosen value escapes | 2.65x (2.48-2.81) | 2.73x (2.58-2.88) |
| kept in a local | 2.28x (2.06-2.54) | 1.72x (1.47-2.05) |
| plain numbers | 1.03x REJ | 0.99x REJ |

The number cells reject cleanly, which is the control the rule needed: it fires
on the *type of the result*, not the shape of the call. An object result is an
allocation; a number result is not.

The local cells were the interesting ones. The obvious objection to the whole
rule is "escape analysis will delete that allocation" — so the workload measures
it. With the chosen value kept in a function local the caller never sees, the
loop still costs 1.72-2.28x. The cost survives. The measurement does not say
why, and the docs do not guess.

**Rule shape.** Fires on `x = f(..., x, ...)` inside a loop when the call's type
is an object and not an array. The target has to be among the arguments: that is
what makes the call a *choice*. `x = x.plus(1)` allocates too, but the value
genuinely changed and an immutable type has no cheaper way to say so.
