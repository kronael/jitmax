turbocharge

mark the function you need fast, and find out what is wrong with it

TL;DR
Mark a function with /** @turbocharge */. turbocharge checks that function and every function it calls against six rules, and gives you the file, the line, the measured cost and the fix. Five rules carry a rerunnable benchmark and the measured case where they must stay silent. The sixth lists what could not be checked.

The walk covers the annotated function and every callee TypeScript resolves to real source. A package that ships a .d.ts binds the call to the declaration, so most typed dependencies are the edge rather than the interior. Every call that cannot be followed is listed by name, and a walk that hits its 200-body cap prints WALK TRUNCATED and is not reported as clean. 

/** @turbocharge */
export function total(rows: Row[]): number { … }

The finding points at dropInner on line 66, not at the annotated function on line 71. Exit codes are the contract: 0 clean, 1 findings, 2 the tool itself failed. A path that does not exist is a 2.

Why the numbers are worth trusting

Every ratio on this page comes from the same protocol, and the raw per-pair timings ship next to every aggregate so you can recompute the intervals yourself.

Rule of the protocolWhy
One fresh OS process per observation An in-process A/B shares inline caches. Contamination is one-way, so the second variant measured is never independent.
AB/BA order randomised across 20 paired runs Order is a confound large enough to invert a result.
Checksums compared inside every pair A variant that computes something different is a failed run, not a fast one.
95 % bootstrap interval; a cell whose interval spans 1.0 is rejected A point estimate without an interval cannot separate a small effect from no effect.
Each side calibrated to a 120 ms timed region, sized from warm cost Sizing from a cold probe starves the slower variant of repetitions and inflates its ratio.
A cell that misses that region by more than 2x throws A mis-sized cell is a different measurement, not a noisy one, and must never reach publication.

The rules are held to the same standard as the code. Each records the condition under which its own benchmark found no effect, and a test asserts it stays quiet there. A rule that fires in a case its measurement rejected fails the build.

Independent confirmation

V8's source sets the same boundary the benchmark found. DEFAULT_MAX_POLYMORPHIC_MAP_COUNT 4 is defined at src/flags/flag-definitions.h:3320 and enforced at src/ic/ic.cc:802, where the inline cache refuses to extend past four valid maps. The measured cliff at the fifth shape and that constant are the same fact reached from opposite directions. It is the only rule here with both, and it is the one to trust most.

The fifth shape is a step, not a slope. Below it the cost is real and small, 1.2x to 2.0x, and it does not rise monotonically. Four maps fit the inline cache and cost a few extra map checks; the fifth does not fit, and the load becomes a hash lookup. That gap is why the rule starts at five.

With object construction counted in the same loop the five-shape cost falls to 1.1-3.5x, because allocation dominates the load. Both halves are measured for every rule.

What it does not claim

These are microbenchmark ratios from one machine (Node v22.23.2, V8 12.4). They establish what a pattern can cost, not what it costs in your workload. turbocharge does not measure your program and never claims a speedup for it.

megamorphic-elements does not check that you load anything. It reads the parameter's type and reports. A function that only reads rows.length triggers it, though nothing there can go megamorphic. Tracked as BUGS TC-8.

No rule enforces the condition in its own third column. Those conditions bound the evidence, not the code. delete-property fires on a single delete, which measured free. chained-allocation cannot see how large your array is. Tracked as BUGS TC-9.

A TypeScript union member is not a V8 map. Shape count is inferred from the declared type, so the rule can fire where no load site ever sees five maps. Tracked as BUGS TC-2.

V8 optimization state is not a speed signal. %GetOptimizationStatus reports optimized=true throughout a 5x megamorphic slowdown. Nothing here uses it.

Run it

Node >=22.18, which strips types itself, so there is no build step. TypeScript >=5.0.0 as a peer dependency — turbocharge loads your copy, so it sees the parse and the types your build sees. 

$ turbocharge src      # check annotated functions under src/
$ make test            # 16 tests, including the must-stay-silent cases
$ make bench           # re-run the 24-cell shape sweep
$ make bench-spread    # re-run accumulating spread
$ make bench-chained   # re-run chained allocation

The five-file demo takes 1.7-2.0 seconds. Almost all of that is TypeScript building a program and type-checking it, which is the price of asking real type questions rather than matching syntax. Cost scales with your program, not with how many functions you annotated. Run it as a build step, not on keystroke.
